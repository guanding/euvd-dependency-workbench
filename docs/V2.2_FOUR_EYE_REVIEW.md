# v2.2 四眼独立复核记录

复核日期：2026-07-28

## 独立路径 A：法规与标准控制

审查对象：CRA Art.3(42)、Art.14、Art.16、ENISA SRP FAQ Q16，以及冻结的
prEN 40000-1-3 工程流程。

初始结论：有条件通过。必须修正技术审批直接形成最终决定、reportable 缺少
结构化证据、awareness 与公开信号/审批时间混淆、SRP 回执未分阶段、Q16
字段不完整、VEX `known_not_affected` 无理由、SBOM 快照缺少 build/hash 失效。

复核后的状态：

- 技术审批仅保存提议，第二个不同账户一致后才写入最终决定；
- `reportable` 绑定恶意行为者、未经许可、实际利用、产品相关性、来源和
  SHA-256；
- external signal、initial assessment、awareness、approval 已分离；
- 三个报告阶段各自保存回执；
- Q16 漏洞字段按 X/C/O/I/A 语义实现；
- 无理由的 `known_not_affected` 降级或拒绝；
- 产品版本、build 或 SBOM SHA-256 变化使未提交结论重开。

结论：对 v2.2 既定的本机报告准备范围为 PASS。不是 CRA 产品符合性结论。

## 独立路径 B：代码、安全与运行

审查对象：SQLite、API、matcher、VEX、前端、Docker、升级与回滚。

初始结论：有条件通过。必须修正审批身份分离、快照新鲜度语义、精确匹配多版本
范围、报告路径越界、重启后 running 任务、外部 CDN 和 SQLite WAL 导出。

复核后的状态：

- 本地审批 profile 使用 scrypt PIN，不同 profile 才能完成两道审批；
- downloaded/checked/age/freshness/last-known-good 已分离；
- 精确标识符会检查全部匹配产品版本范围；
- 报告只能从 `OUTPUT_DIR` 下载；
- 重启中断任务标记 failed，旧 completed 任务幂等登记；
- 运行界面不再访问外部 CDN；
- Windows WithData 迁移使用 SQLite online backup；
- Docker 非 root、read-only root filesystem、cap drop、no-new-privileges 和
  localhost 端口绑定继续生效。

结论：对单机 Docker 试运行范围为 PASS。多人共享前仍需完整认证、RBAC、
TLS、现实身份映射、集中备份和远端防篡改审计。

## 汇总结论

两条独立路径对以下结论一致：

1. v2.2 可作为 SBOM→EUVD/KEV→产品适用性→Art.14 人工决定→SRP 手工准备的
   受控工作台；
2. 公开 KEV/EUVD 信息不得直接等同 CRA Art.3(42) 最终事实；
3. awareness 只能人工确认，且不能等待审批完成才启动时限；
4. 未满足产品级证据和四眼门槛时不能生成 `reportable` 最终决定；
5. 不自动提交 SRP，不主张 prEN 草案带来的符合性推定。

剩余限制属于部署范围而非本次代码缺陷：真实身份和授权由制造商程序控制，
正式 SRP URL/EU Login/CSIRT 协调员和真实回执须在平台现场验证。
