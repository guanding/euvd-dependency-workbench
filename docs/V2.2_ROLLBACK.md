# EUVD Dependency Workbench v2.2 回滚与恢复

## 1. 回滚前备份

先停止写入：

```text
docker compose down
```

将整个 `data/` 和 `outputs/` 复制到带时间戳的受控备份位置。必须同时保留
`workbench.sqlite3` 以及可能存在的 `workbench.sqlite3-wal`、
`workbench.sqlite3-shm`；更稳妥的方式是在服务停止后执行 SQLite backup。

Windows 便携包使用 `export-portable.cmd` 的 `-WithData` 路径时，v2.2 已改用
SQLite online backup 生成一致数据库，而不是只复制主数据库文件。

## 2. 应用回滚

v2.2 没有删除或重写 v2.1 扫描任务 JSON。若需要回退应用镜像：

1. 停止 v2.2；
2. 备份当前 `data/` 和 `outputs/`；
3. 将 compose 的 image/build 源恢复到已验证的前一版本；
4. 启动并确认 `/api/health`；
5. v2.1 不读取 `workbench.sqlite3`，但原扫描项目和 Excel 报告仍保留。

不要把 v2.2 的 SQLite 文件转换回 v2.1 JSON，也不要删除它；以后恢复 v2.2
时仍需使用。

## 3. 数据恢复

1. `docker compose down`；
2. 保存当前损坏/待分析的数据副本；
3. 用完整备份恢复 `data/` 和 `outputs/`；
4. 检查目录权限允许容器 UID `65532` 写入；
5. `docker compose up -d`；
6. 检查健康状态、案件数、审批/证据/回执及最近审计事件。

恢复后必须人工复核截止时间。停机或回滚不会暂停 CRA Art.14 法定时限。

## 4. 失败判据

出现以下任一情况应停止使用报告决定功能，保留只读证据并恢复：

- SQLite integrity check 失败；
- SBOM snapshot hash 与源文件不一致；
- 两道审批被同一账户完成；
- awareness 无授权账户、依据或证据引用；
- feed 为 unavailable，但界面把未命中显示为无利用；
- SRP 草稿出现自动提交成功的表述而没有真实平台回执。
